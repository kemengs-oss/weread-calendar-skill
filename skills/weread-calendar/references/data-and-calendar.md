# 数据与排期

输入为数组或 `{ "items": [...] }`。每条必需字段：id、book_id、text、highlighted_at（有效 ISO 日期时间）。展示字段：book、author、chapter、highlighted_date（YYYY-MM-DD）、reader_link（可空）。所有示例来源必须可追溯；虚构示例明确标注。

输入和生成目录都属于用户个人数据，不写入技能目录或源码仓库。输出 highlights.json 仍含用户原文，部署默认私有；静态托管访问策略应保护全部 JSON 及 HTML，不只保护首页。

初始化按导入日筛掉未满 min_age_days 的划线，再将候选排入指定年的每一天。因此早于划线日期的日历安排是回顾计划，不是“当时已划线/已发送”的证明。max-length 是完整划线的选择上限，不能为了凑长度改写原文。

算法按以下顺序选取：优先未用过的原文、避免上一本书、减少最近五天重复书籍、平衡书籍累计频次、稳定散列排序。同一原文 ID 是 book_id + id，文本不自动跨书合并。候选不足一年时会循环；summary.unique_quotes 显示实际不同原文数。要实现长期无限不重复必须补充数据。

build：目标年已存在时失败；rebuild：只有用户授权重排时使用。日历持久化在输出文件中，日常打开不重排。

update：今天按所选时区计算，今天和所有过去条目不变。新 ID 去重入库，进入 pending_ids；达到最小年龄后才能安排。每轮最多 min(7, ceil(未来日期数*20%))，优先避开前后邻日相同书籍。重复导入不会重复替换。未安排的新增书摘保留队列，旧原文不删除。部署静态站时更新文件后须重新发布，不能声称后台数据库已更新。
