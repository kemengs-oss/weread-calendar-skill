# 部署与定时运行

本包生成纯静态网站，自带浏览器端 PNG 导出，不要求安装截图服务器。代码与字体不从第三方 CDN 加载。支持域名根路径和 GitHub Pages 项目子路径；assets/site/vendor 的 html-to-image 1.11.13 以 MIT 许可附带，保留许可证。

用户要求部署时，使用当前环境提供的托管工具及其技能；例如 Sites 可托管私有站点。为新用户生成新站点，不能复用原开发者的 project_id、域名或源码仓库。没有托管工具或权限时保留可用目录，说明未部署，不编造链接。

个人数据默认私有。明确授权公开后才能公开包含原文的数据文件。GitHub 发布只推技能代码，不能把生成站点的数据目录加入 Git。技能使用者即使在私有仓库也应把个人书摘与代码分开。

用户要求每日推送时，先明确时区、时间、接收渠道与对话模式。可由云端任务打开托管的当天卡片、截图、展示真实图片及原书链接。任务需要授权访问私有站点、真实可用的云端浏览器/截图能力及跨运行的数据存储；云任务不得引用开发者电脑绝对路径。先在目标运行环境验证访问与截图，再区分“已保存任务”和“已跑通”。

每周同步：用户授权的云端连接 -> 导入新划线 -> calendar.mjs update -> 发布同一私有站点 -> 回读，确认今天和过去安排没变化。仅有本地环境变量时不具备无人值守云端同步能力。

不默认发送邮件或建定时任务。邮件需要用户授权的发信渠道、收件地址及内容，密钥走宿主密钥存储。仅“API 受理成功”不能声称进收件箱，应区分受理、投递及用户实际收到。
