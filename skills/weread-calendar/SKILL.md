# 微信读书万年历

生成属于用户的书摘日历，保留原文、书名、作者、章节和划线日期。先交付可运行页面，再按用户要求部署或设置推送。

## 选择数据入口

- 用户已有导出文件：直接使用，不要求提供 API Key。格式见 [数据与排期规则](references/data-and-calendar.md)。
- 用户要求读取个人微信读书划线：先读 [读取与凭据](references/weread-access.md)，确认选书范围。默认从不同书籍轮询采样至多 1000 条，排除最近 14 天；用户的明确设置优先。不要重新读取用户未授权的数据范围。
- 没有数据或凭据：可用 `--demo` 验证页面，但明确标注演示内容是虚构文字，不能说已读取用户书摘。

## 生成页面

要求 Node.js 18+；官方接口导入额外要求 Python 3.9+。以下命令中的 `<skill>` 指本 SKILL.md 所在目录；输出目录选用户工作区中一个新的目录。

```sh
node <skill>/scripts/calendar.mjs build --input <highlights.json> --output <site-directory>
```

可选：`--year`、`--timezone`（默认 Asia/Shanghai）、`--min-age-days`（默认 14）、`--max-length`（默认 220）、`--as-of YYYY-MM-DD`。年份默认当前年份。

无数据预览：

```sh
node <skill>/scripts/calendar.mjs build --demo --output <site-directory>
```

输出为静态网站，包括全年日期安排、导入书摘及页面模板。用 HTTP 服务预览，不使用 `file://`；部署在域名根路径。既有日历拒绝重复 build，避免悄悄改变过去安排。用户明确要求重排时用 `rebuild`。

## 保留的产品规则

- 日期前后翻页；满一年有 365/366 个日期。当前年份外的“回到今天”禁用。
- 14 天限制用于入库筛选，不套用到日历的过去日期，避免年初全为空；这是阅读安排，不是历史推送记录。
- 首先使用未展示过的书摘，尽量避免相邻同书，并平衡书籍频率。候选不足全年时允许循环，但必须报告重复数量，不能声称全年不重复。
- 五种主题：黑白、鼠尾草绿、暖杏柔粉、缤纷撞色、深蓝夜读；切换时保留日期和内容。
- 页头为“每日书摘 / DAILY READING”。页面只保留日历。底部磨砂悬浮栏：昨天、回到今天、明天、换主题、下载；为底部正文留出滚动空间。
- 下载只导出卡片为 2 倍 PNG，不含按钮和提示。失败显示重试提示，不能假报已保存到设备相册。
- 原书链接只使用已验证的接口链接，不能承诺定位到划线位置。

## 增量更新

```sh
node <skill>/scripts/calendar.mjs update --input <new-highlights.json> --output <existing-site-directory>
```

只动今天之后的安排，去重后每次最多替换 7 天，且不超过剩余天数的 20%；剩余新增书摘排队等待。新书摘仍需达到日历配置的最小年龄。保留历史条目引用的旧书摘。自定义上限用 `--replace-limit`。更多约束见 [数据与排期规则](references/data-and-calendar.md)。

## 验证与交付

检查全年日期、跨书间隔、可用书摘及重复数量。实际操作翻页、回到今天、主题切换和下载，至少检查 320px 与 390px 宽度；没有浏览器时明确说明视觉/下载未经验证。

部署和推送只有用户要求时执行：读 [部署与定时任务](references/deployment-and-schedules.md)。生成网站不等于发布，保存任务不等于云端成功运行。个人书摘默认私有；开源仓库只放代码和虚构样例，不上传真实书摘、日历数据、邮箱、密钥或既有站点身份。
